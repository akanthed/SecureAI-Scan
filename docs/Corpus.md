# Recall corpus

A reproducible check of MCP013 (command injection) recall and precision against published CVEs, small refactors of them, and a set of unrelated servers. Run it with:

```bash
npm run corpus                       # everything
npm run corpus -- --only CVE-2025-52573
npm run corpus -- --clean-only
npm run corpus -- --json corpus/last-run.json
```

Third-party source is never vendored. `corpus/cases.json` and `corpus/clean.json` pin repositories to full commit SHAs; the runner clones them into the gitignored `.corpus-cache/`.

## Method

1. **CVE pairs.** For each of six published MCP command-injection CVEs, the vulnerable commit must produce at least one `proven` or `likely` finding for the expected rule, and the fix commit must produce none. `heuristic` findings do not count.
2. **Recall mutations.** Patches in `corpus/mutations/<case>/recall-*.patch` are applied on top of the vulnerable commit. Each is a harmless refactor (an alias, an extra wrapper, a cross-file move). The finding must survive.
3. **Guard mutations.** Patches named `guard-*.patch` are applied on top of the fix commit. Each writes a real guard in a different style. The scanner must stay silent.
4. **Clean set.** Unrelated public MCP servers and frameworks at pinned SHAs must produce zero default-tier MCP013/MCP014 findings.

Patches are generated by `scripts/corpus/make-mutations.js`. A patch that fails to apply is reported as a patch error, never as a recall miss.

## Results

From `corpus/last-run.json` (secureai-scan 0.12.0, 2026-10-27):

| Check | Passed |
|---|---|
| Vulnerable commits fire | 6 / 6 |
| Recall mutations still fire | 18 / 18 |
| Fix commits clean | 6 / 6 |
| Guard mutations clean | 17 / 17 |
| Clean-set servers silent | 26 / 26 |

## Adding a case

1. Add an entry to `corpus/cases.json` with `id`, `repo`, `vulnerableSha`, `fixSha`, `rule`, and `tool`.
2. Add mutations to `scripts/corpus/make-mutations.js` and regenerate. Check each with `git apply --check`.
3. Run `npm run corpus -- --only <id>`.

Do not edit a patch to make it pass. A failing mutation is a recall gap in the rule; fix the rule and add a fixture under `test-fixtures/`.

## Scoring another scanner

`--scanner-cmd "<cmd with {dir} and {out}>"` runs any command that scans `{dir}` and writes a report to `{out}` in this scanner's JSON report shape. `--json <path>` writes the totals and per-case results.

## Limits

Six CVEs, one rule family (MCP013; the clean set also checks MCP014). The mutations are hand-written and cover three refactor styles. This shows the scanner survives those refactors and stays quiet on 26 unrelated servers. It does not show general recall on unseen code.
